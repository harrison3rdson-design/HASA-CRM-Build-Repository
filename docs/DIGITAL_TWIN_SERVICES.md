# Digital twin services

## Operator workflow

1. Add the property manager / facility owner as a Client. Open Properties to create each property's address, area and access notes.
2. Create a Proposal. Keep initial capture and CAD charges in the existing service lines. Enable Recurring Property Services and select an editable launch-price preset or enter custom pricing. Identify covered properties, model capacity, maintenance allowance, refresh work, transfer and retention in the scope.
3. Send through the existing proposal workflow. The customer must explicitly acknowledge recurring fees and the fixed term. Recurring terms are stored with the locked revision, acceptance snapshot and executed PDF. Existing proposals with no recurring services retain their current behavior. Manual verbal/email acceptance is intentionally unavailable for proposals with recurring terms.
4. On the accepted proposal, choose Set Up Recurring Agreement. Link properties belonging to that client and activate with the agreed start date. Creation is idempotent per accepted revision. Coverage and pricing are fixed after activation; a changed scope or renewal requires a new accepted proposal.
5. Record model links under each property, including separate historical versions and actual platform capacity. Audience labels do not change Matterport permissions. No credentials should be embedded in model links.
6. The existing protected daily maintenance job generates due monthly draft invoices. You can also generate due drafts from the agreement. Review and send through Billing; no customer messages or payment collections happen automatically.
7. Log remote maintenance minutes and schedule refresh visits on the agreement. Included minutes reset each calendar month with no rollover. Capacity and maintenance overages produce a notice, not an automatic charge. Visit funding and scope must be reviewed before dispatch.

## Billing behavior

- Separate service billing projects (`SVC-…`) preserve capture-project budgets and supply the existing invoice/PDF/payment flow with its required project relationship. The billing record inherits the proposal's primary contact. It is excluded from normal work-entry / invoice-creation selectors and the active capture-project dashboard metric.
- One agreement can cover multiple properties and generates one monthly invoice across that portfolio.
- A fixed month offset from the original start date prevents January 31 billing from drifting to March 28. Term end is exclusive; there is no automatic renewal.
- Row locks and a unique agreement/period index prevent duplicate invoices on retries or overlapping runs. Backdated activation creates every due period. Recurring drafts cannot be deleted through the project invoice-number-release action.
- Recurring invoices are Due on Receipt; the due date is assigned on sending using America/New_York. Existing NET 15/30/90 behavior is unchanged.
- Cancellation stops future generation; it does not void existing invoices, settle early-termination charges, disable hosting, or collect money.
- Dashboard MRR includes service and scheduled-refresh monthly fees only for active agreements whose term includes today. Annualized revenue is MRR × 12, not guaranteed future revenue.

## Security and verification

New tables use explicit grants, RLS and the existing single-company internal-role/AAL2 checks. Browser writes and anonymous access are not granted. Server actions authenticate and authorize before using the privileged database client. Billing functions are callable only by service_role. Recovery backups include all new tables.

Validation: TypeScript, Next.js production build, existing regression suite plus recurring-input tests, and transactional SQL integration checks in `tests/sql/digital_twin_services.sql`. SQL fixtures are rolled back; no client emails or payments are generated by testing.

The local sandbox lacks /proc memory metrics. A temporary tooling-only memory-metrics adapter was used to run Vitest and Next build; it is outside the repository and is not deployed. The production deployment builds without that adapter.
